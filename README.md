## 프로젝트 개요

### 문제 인식
- 일반 사용자들은 계약서나 판례 같은 법률 문서를 읽고 이해하기 어려움
- 법률 용어는 전문적이고, 문서 길이가 길어 핵심 내용 파악이 어려움
- 변호사 상담 비용이 부담되어 법률 정보 접근성이 낮음

### 해결 방안
- **LLM 기반 자동 분류**: 사건 내용을 입력하면 도메인(형사/민사/가사 등)과 쟁점을 자동 분류
- **유사 판례 검색**: 입력된 사건과 유사한 과거 판례를 벡터 유사도 기반으로 검색
- **RAG 기반 상담**: 판례 데이터를 기반으로 법률 질문에 답변하는 AI 챗봇
- **승소 확률 예측**: 유사 판례 분석을 통한 예상 승소율 제공

### 목표
- 법률 문서를 자동 분류 → 요약 → 질의응답 형태로 처리
- 사용자가 쉽게 이해하고 활용할 수 있는 챗봇 형태의 서비스 구현

## 주요 기능

### 1. 사건 검색 시뮬레이션 (탭1)

| 기능 | 설명 | 기술 |
|------|------|------|
| **사건 도메인 분류** | 입력된 사건 내용을 형사/민사/가사/행정 등으로 자동 분류 | GPT-4o-mini |
| **키워드 추출** | 사건에서 핵심 법률 키워드 8~15개 자동 추출 | LLM + KoNLPy |
| **유사 판례 검색** | 추출된 키워드로 유사 판례 검색 (AND → OR 폴백) | Regex + Pandas |
| **승소 확률 예측** | 유사 판례의 결과 분석을 통한 예상 승소율 계산 | 통계 기반 |
| **참조조문 설명** | 판례에 인용된 법률 조문을 쉽게 설명 | GPT-4o-mini |

### 2. RAG 기반 상담 챗봇 (탭2)

| 기능 | 설명 | 기술 |
|------|------|------|
| **판례 기반 질의응답** | 약 3만 건의 판례 데이터 기반 법률 상담 | LangChain RAG |
| **PDF 업로드** | 사용자 문서 업로드 후 해당 문서 기반 상담 | PDFPlumber |
| **대화 히스토리** | 이전 대화 맥락을 유지한 연속 상담 | Session State |
| **스트리밍 응답** | 실시간 타이핑 효과로 답변 표시 | Streaming |
| **출처 명시** | 답변의 출처가 판례인지 모델 지식인지 구분 | Prompt Engineering |

```python
# 2순위: KoNLPy 형태소 분석
def konlpy_extract(text):
    okt = Okt()
    nouns = okt.nouns(text)
    priority = ['마약', '성폭행', '음주운전', '사기', ...]
    return [w for w in nouns if w in priority]

# 3순위: Simple 키워드 매칭
def simple_keywords(text):
    priority = ['마약', '성폭행', '음주운전', ...]
    return [w for w in priority if w in text]
```

```python
rate -= 피해금액 / 10000  # 피해금액 영향
```

### 3. RAG 체인 구성

```python
chain = (
    RunnableMap({
        # 1. 질문으로 관련 문서 검색
        "context": itemgetter("question") | retriever | join_docs,
        # 2. 원본 질문 유지
        "question": itemgetter("question"),
        # 3. 대화 히스토리 포함
```
